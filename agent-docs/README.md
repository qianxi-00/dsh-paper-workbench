# Agent 协作资料

这里保存开发本项目时可跨会话、跨机器复用的工程资料，随源代码提交并同步到 Git 远端。它属于插件仓库，不是 DSH 用户数据目录，也不是插件为论文阅读会话部署的技能目录。

## 从哪里开始

1. 先读根 [AGENTS.md](../AGENTS.md)，确认本次任务的工程边界。
2. 读 [项目状态与证据](memory/project-state.md)，核对记录日期、分支和未验事项；这些是快照，接手时重新检查 Git 与当前环境。
   任务生命周期、失败运行及 Loop 调度边界另见 [2026-11-25 任务与运行盘点](memory/2026-11-25-task-run-audit.md)。
3. 涉及实现时按 [架构索引](memory/architecture.md) 找源码、契约与测试；涉及远端、市场、安装或版本发布时读 [仓库与发布运维](operations/release-and-distribution.md)。
4. 接续较大任务时，再读相应 [计划](plans/README.md)、[任务记录](tasks/README.md) 和 [交接](handoffs/README.md)。按需阅读，不把全部历史文档自动塞进每次上下文。

## 分类与唯一归属

| 目录 | 保存什么 | 不承担什么职责 |
| --- | --- | --- |
| [memory](memory/) | 稳定架构、决策依据、当前状态和带证据的已知边界 | 不复制源码常量、完整变更日志或原始聊天 |
| [plans](plans/README.md) | 多步骤工作的范围、方案、依赖、验收和阶段进度 | 不把设想写成已实现行为 |
| [tasks](tasks/README.md) | 可执行任务、状态、阻塞、验证结果和后续动作 | 不以待办勾选代替实际验证 |
| [handoffs](handoffs/README.md) | 某一时刻的接手入口、工作区状态、未完事项与证据 | 不成为另一份持续更新的项目事实库 |
| [operations](operations/release-and-distribution.md) | 远端仓库、市场渠道、CI/CD、打包、安装及发布检查 | 不保存凭据或实际 profile 的个人配置 |

已有 [docs/plans](../docs/plans/) 保留为历史计划入口，避免破坏引用；新增开发计划统一放本目录。接口契约仍在 [docs](../docs/)，用户说明仍在 [README.md](../README.md) 和 [使用指南](../docs/guide.md)，发布沿革仍在 [CHANGELOG.md](../CHANGELOG.md)。同一事实只维护一处，其他位置用链接引用。

## 记录规则

- 文件名使用可读主题；阶段记录采用 `YYYY-MM-DD-topic.md`。持续维护的架构、状态和运维索引使用稳定文件名。
- 记录注明日期、涉及分支或提交、事实来源，以及“已验证 / 静态推断 / 待验证”的区别。引用远端运行时保留具体 URL、运行 ID 和结论；引用源码时给仓库相对路径，重要版本用固定 SHA 的 GitHub 链接。
- 跨文件、跨会话或有阶段交付的工作建立计划和任务记录；小修改可以补记到已有任务，不为每一轮聊天生成文档。
- 计划调整时写明原因；任务完成时补验证命令、退出码、跳过项与交付位置。修复后更新当前状态，旧快照保留日期，防止历史问题继续冒充当前限制。
- 会影响后续接手的设计选择写入 memory；过程细节留在 plans/tasks。交接只列接手所需内容，并链接这些事实源。
- 不写 token、密码、cookie、带凭据 URL、个人绝对路径、原始论文全文、真实文库备份、模型对话全文、日志转储和临时产物。必要例子使用脱敏的仓库相对路径。
- Git 可以跟踪这些 Markdown；运行时数据、PDF、`.env`、缓存与大体积产物继续遵守 [.gitignore](../.gitignore)。当前 npm 发布白名单没有本目录，Git 同步与运行包发布分别核对。

## 收尾与同步

完成任务后核对根指南导航、相对链接、文档中的命令和最终 diff。只有实际执行并查看结果，才写“验证通过”。将有用的新结论归入对应分类，再按根指南的分支规则提交；检查 Git 跟踪范围和远端提交后，才能报告已同步。提交、合并、发版和修改本机插件安装是不同操作，均按当前用户授权范围执行。
